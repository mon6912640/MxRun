# 现代快速启动器设计方案
## —— 基于 AltRun 理念的 2026 重构蓝图（改进版，非复刻）

> 日期：2026-09-13
> 前提：保留 AltRun 的交互灵魂（全局热键 + 键盘流 + 受控数据规模），
> 彻底解决其三个历史顽疾：**崩溃丢数据、视觉陈旧、单线程性能天花板**。

---

## 1. AltRun 哪些设计已经过时

| 维度 | AltRun 现状 | 为什么过时 |
|---|---|---|
| **数据存储** | 单个 INI 文件，`IniWrite` 直接覆盖 | **这是崩溃丢数据的根因**：无事务、无原子写、无备份；写到一半进程被杀 → 文件截断；放 OneDrive 等云同步目录还会触发写冲突（源码注释里就有 "The cloud operation is invalid" 的抱怨） |
| **数据加载** | 每次执行命令后 `LoadCommands()` 全量重载 + 全量重排序 | 写放大 + 卡顿源；命令多了以后每次启动一个程序都伴随一次 IO 尖峰 |
| **排序模型** | 纯频率计数（SmartRank），只增不减 | 2010 年代的做法。现代启动器普遍用 **Frecency**（频率 × 时间衰减）：三年前用过 500 次的软件不该永远排在昨天装了用 3 次的新软件前面 |
| **匹配算法** | 子串 / `.*` 连接的保序正则，命中即取前 N 条 | 只能"过滤"不能"打分"。现代方案（fzf/nucleo 类算法）对每个候选计算匹配质量分：连续匹配、词首匹配、短路径都加分，排序质量天差地别 |
| **拼音** | GBK 码表首字母 | 只支持首字母缩写，不支持全拼、不支持混合输入（`文j`），生僻字失配 |
| **搜索时机** | 每次击键在 UI 线程同步全量重扫 | 无防抖、无增量过滤、无取消。现代做法是：击键 → 防抖 10–30ms → 后台线程在上轮结果集上增量过滤 → 可取消 → 流式回填 |
| **视觉** | Win32 原生 ListView + 贴图背景 + 打补丁的暗色模式 | 无动画、无高分屏适配、无圆角阴影体系、无毛玻璃；暗色模式靠 `DllCall` 硬改控件颜色 |
| **扩展机制** | INI 里写 `FUNC | 函数名`，耦合主程序 | 无法第三方扩展；现代启动器都是插件生态（Flow/Wox/Raycast 的增长引擎） |
| **崩溃处理** | AHK 单进程，任何未捕获异常直接弹框/退出 | 无崩溃守护、无状态恢复、无日志转储 |

**没过时、必须保留的**：热键呼出的交互模型；"不建全盘索引、数据规模受控"的性能哲学；Fallback 兜底列表；空格分词保序匹配的直觉性；绿色便携。

## 2. 产品定位

**一句话**：AltRun 的精神续作——保留它"轻、快、键盘流"的 DNA，用 2026 年的技术把可靠性、匹配质量和视觉体验拉到 Raycast（macOS）同级，同时坚持 Windows 原生、开源、便携。

**非目标**（明确不做，防止膨胀）：
- 不做全盘文件搜索引擎（交给 Everything IPC 集成）
- 不做 Electron/Web 技术栈的 UI
- 不做账号体系和云同步（数据本地优先，同步交给用户自己的网盘）
- 首版不做跨平台（Win32 集成是核心价值，跨平台会稀释它）

## 3. 视觉与交互设计（美观层）

### 3.1 设计语言：Fluent Design + 克制

对齐 Windows 11 原生审美，让启动器看起来像系统自带功能，而不是外来软件：

- **材质**：Mica / Acrylic 毛玻璃背景（DWM `DwmSetWindowAttribute` + `SetWindowCompositionAttribute`，或直接用 WinUI 3 的 Mica 实现），跟随系统明暗主题自动切换
- **形态**：悬浮圆角卡片（圆角 8–12px）+ 柔和投影，无边框、无标题栏，呼出时 120–180ms 的淡入 + 轻微上浮（translateY 4–8px）动画，消失 80ms——动画要短到"感觉跟手但不拖沓"，启动器的动画预算比任何应用都苛刻
- **排版**：搜索框大字号（18–20pt）无边框内嵌卡片顶部；结果行高 40–48px，图标 24–32px，双行布局（主标题 + 次要路径/描述灰色小字）
- **高分屏**：Per-Monitor DPI Aware v2，图标用 SVG 或高分 ICO，杜绝 125%/150% 缩放下发虚

### 3.2 结果列表的信息层级

AltRun 的列表是"序号 | 类型 | 路径 | 描述"四栏表格——这是工程师视角。改为用户视角的卡片行：

```
┌─────────────────────────────────────────────────────┐
│  🔍  eve                                        ⎘   │
├─────────────────────────────────────────────────────┤
│  ⚡ Everything                    文件搜索 · 常用      │
│  📁 C:\Apps\Everything.exe       应用程序             │
│  🌐 用 Everything 搜索 "eve"      兜底 · Enter 执行    │
└─────────────────────────────────────────────────────┘
```

- 图标优先，类型用右上角小标签或次要行文字表达，不再占一栏
- 匹配命中的字符**高亮加粗**（fzf 式），让用户理解"为什么是它被匹配到"
- 右侧或底部**预览区**（可选开关）：选中图片/文档时显示缩略预览——Raycast 验证过的体验加分项
- 当前选中项的操作提示常显在底部栏（`Enter 打开 · Ctrl+D 定位 · Tab 补全`），替代 AltRun 的 F1 帮助页

### 3.3 交互细节现代化

- **Tab 智能补全**（AltRun 当年"不为也"的决策在 2026 年值得重议）：Tab 补全到唯一公共前缀，不自动执行、可继续编辑——零风险纯收益
- **结果分组**："常用 / 应用程序 / 命令 / 网页 / 兜底操作"分组显示，组间细分割线
- **命令面板模式**：`>` 前缀进入子命令空间（如 `>r` 重载、`>s` 设置）——VS Code/Raycast 验证过的扩展交互，比 AltRun 的 `+`/空格/`>` 三个散装前缀更体系化
- **拖拽即录入**：把文件/链接拖到悬浮窗上直接弹出"创建快捷项"——保留 SendTo 之外的现代入口
- **设置 GUI 化**：INI 手写配置降级为高级选项，常规配置全部 GUI 化，改配置不再需要重启

## 4. 技术架构（性能层）

### 4.1 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | **Rust** | 内存安全（直接回应"经常崩溃"）、单 exe 分发、常驻内存可压到 15–30 MB、windows-rs 提供完整 Win32/COM 绑定 |
| 搜索内核 | **nucleo**（helix 编辑器的匹配库）或 skim/fuzzy-matcher | 异步、worker 线程池、支持流式增量结果、内置 Unicode 和打分，比手写正则高一个数量级 |
| 拼音 | **pinyin crate / 内置全拼表** | 支持全拼 + 首字母 + 混合匹配 |
| UI | 两条路线（见 4.2） | — |
| 存储 | **SQLite（WAL 模式）** | 见第 5 节，这是可靠性的基石 |
| 异步 | tokio（轻量特性集） | 搜索、索引、IO 全部离开 UI 线程 |
| 插件 | 首版：子进程 + JSON-RPC over stdio；远期：WASM（wasmtime） | 崩溃隔离：插件崩了主程序不死 |
| Everything 集成 | **Everything IPC / SDK（es.exe 或命名管道）** | 替代 AltRun 的命令行转发，结果直接进自己的列表 |

### 4.2 UI 路线决策（本项目最关键的取舍）

**路线 A：Rust 原生自绘（egui / 自研 + Direct2D）**
- 常驻内存 15–30 MB，启动 < 50ms，视觉完全可控
- 代价：所有控件自己搭，设置页、右键菜单等工作量大
- 适合：追求极致轻量、核心交互简单（输入框+列表恰恰是自绘最擅长的形态）

**路线 B：WinUI 3 / WPF（C# AOT）**
- Mica、Fluent 控件、动效开箱即用，视觉天花板高，工程化成熟
- 代价：常驻内存 60–100 MB，启动 200–400ms，打包体积大
- 适合：团队开发、重视设置页等复杂 UI、接受资源占用

**推荐：路线 A（Rust + egui 起步），核心原因**：启动器的 UI 复杂度极低（一个输入框、一个列表、一个设置页），自绘成本可控；而"常驻内存"和"呼出延迟"是这个品类的生命线。egui 的即时模式对"每帧都在变的搜索列表"反而比 retained GUI 更顺。若后期设置页膨胀，再评估把设置拆成独立 WinUI 小进程。

### 4.3 搜索流水线（替代 AltRun 的同步全扫）

```
击键 ──► 防抖 15ms ──► 生成 SearchQuery(带 generation id)
                          │
                          ▼
              ┌── 前缀缓存命中？── 是 ──► 在上轮结果集上过滤 O(上轮命中数)
              │ 否
              ▼
        nucleo worker 线程池全量匹配（可被取消）
              │  打分 = 匹配质量分 × frecency 权重
              ▼
        流式回填 UI（generation 过期即丢弃）
```

- **增量过滤**：击键序列天然前缀递增，90% 的击键只需在上轮几十条结果里继续筛，这是 AltRun 完全没有的优化
- **可取消**：新输入到来立即取消旧任务，杜绝"输入快时列表闪烁追赶"
- **打分模型**：`最终分 = w1·匹配质量（连续性/词首/长度惩罚）+ w2·frecency + w3·类型先验`
- **Frecency**：`score = Σ 访问次数 × 时间衰减(半衰期 ~14 天)`，替代 SmartRank 的单调递增计数

### 4.4 性能预算（写进 CI 的硬指标）

| 指标 | 预算 | 对比 |
|---|---|---|
| 常驻内存（空闲） | ≤ 30 MB | AHK 版 5–10 MB / WinUI 路线 60–100 MB |
| 冷启动到可输入 | ≤ 100 ms | AHK 版 ~50ms（唯一会输的项，可接受） |
| 热键呼出到可见 | ≤ 50 ms | 窗口常驻内存只隐藏，不销毁 |
| 击键到结果更新（1 万条快捷项） | ≤ 16 ms | AHK 版在 3000 条时已可感知 |
| 索引重建（1 万文件） | 后台 ≤ 3 s，不阻塞 UI | AltRun 前台进度条阻塞 |

## 5. 数据可靠性专项设计（回应"崩溃丢数据"）

这是本次重构的**一号工程**，AltRun 的 INI 方案每一处都要反着做：

1. **SQLite + WAL 模式**：所有快捷项、frecency 统计、配置入库。WAL 提供崩溃安全的原子提交——进程任何时候被杀，已提交的事务不丢，未提交的干净回滚。INI 的"写一半"问题在事务模型下不存在。
2. **写路径纪律**：frecency 更新走"内存累积 + 每 5 秒/退出时批量提交"，消除 AltRun"每执行一次命令就全量重载 + 写盘"的 IO 尖峰；`PRAGMA synchronous = NORMAL`（WAL 下崩溃安全且快）。
3. **自动备份与版本化**：每次启动时若库有变更，滚动保留最近 10 个备份副本（`backups/launcher-YYYYMMDD-HHMMSS.db`）；数据库损坏时自动从最近备份恢复并提示，而不是让用户面对空列表。
4. **导入导出为人类可读格式**：一键导出/导入 JSON 或 TOML（兼容迁移 AltRun 的 INI），数据主权归用户，备份、git 管理、跨机迁移都可行。
5. **崩溃守护**：全局 panic hook → 捕获后写 minidump + 当前状态到日志目录 → 显示友好错误而非裸崩；主窗口进程与索引进程分离（可选），索引崩溃不影响快捷项数据。
6. **云目录防御**：检测到数据目录位于 OneDrive/Dropbox 等同步目录时，主动提示迁移或开启"本地库 + 导出同步"模式——直接回应 AltRun 源码里的 cloud operation 报错。

## 6. 功能规划

**MVP（v0.1，验证核心体验）**
- 全局热键呼出、毛玻璃卡片 UI、动画
- nucleo 模糊搜索 + 打分排序 + 高亮 + 增量过滤
- 快捷项 CRUD（GUI）、拖拽录入、SendTo
- SQLite 存储 + 备份 + AltRun INI 导入器
- Fallback 兜底（Everything IPC / 网页搜索 / 计算器）
- 拼音全拼 + 首字母

**v0.2–0.3**
- Frecency 自学习排序、命令面板（`>` 前缀）
- 计算器（meva/evalexpr，支持单位换算）、剪贴板历史
- 类 Listary 快速切换目录（AltRun 的窗口组方案用 windows-rs 重写）
- 插件系统（子进程 JSON-RPC）+ 首批插件：Everything、winget、系统命令（关机/锁屏）

**v1.0**
- 结果预览区、主题自定义、便携/安装双分发
- WASM 插件沙箱、插件市场清单

## 7. 一句话总结

> AltRun 的交互是经典，实现是古董。重构的本质是三件事：**用 SQLite 事务换掉 INI（治丢数据），用 Rust 异步流水线换掉单线程全扫（治卡顿），用 Fluent/Mica 换掉 Win32 贴图（治颜值）**——其余全部是对 AltRun 产品判断的致敬而非推翻。
