## 2. 已验证的事实（都有实测证据，别再重新怀疑）

### 2.1 性能（README「性能实测」节有完整表格）

| 指标 | 实测 | 备注 |
|---|---|---|
| 热键按下 → 首帧渲染 | **1.2–5.9 ms**（p50 ~3.7ms） | 设计预算 50ms，余量一个数量级；59 条数据下复测仍是 **2.5–3.9 ms** ✅ |
| 私有提交（常驻，与显隐无关） | **~106–157 MB** | 真实占用看这个 |
| 工作集（显示中） | ~130–270 MB | 含 GPU 映射 |
| 工作集（隐藏数小时后） | ~11 MB | **只是系统 trim 的结果，不是真实占用** |
| 线程 | 27 | glow 后端 |
| 冷启动 → 首帧 | **~255–295 ms**（59 条数据） | 拆解：eframe/GL/字体初始化占掉绝大部分，**我们自己的数据只花 0 ms** |
| 冷启动 → 图标齐 | **~430–450 ms** | 首帧后 ~175 ms 内补齐可见行的图标（emoji 先顶上） |

**图标加载在 2026-09-14 重做过（原来是冷启动最大的开销）**：

- 老做法：启动时**阻塞预热全部**图标，再显示窗口。实测 **6 条 49–67 ms → 59 条 544–770 ms**（线性增长）。也就是冷启动约 `250 ms(框架) + 600 ms(图标) ≈ 850 ms`，而且**条目越多越慢**——正是"后面越来越多会卡顿"的那条路。
- 新做法：**按需 + 后台 + 有上限缓存**（`Icons`）。索引建完就出窗口（0 ms），行渲染时才请求自己那一行的图标，worker 线程取像素，UI 帧里上传纹理；缓存上限 256（顺带修掉"缓存无上限"那条欠账，对将来的文件搜索很关键）。
- 附带：`main` 里还起了个短命线程，在 eframe 初始化期间**提前把 shell 映像子系统预热掉**（首次 `IShellItemImageFactory` 调用要 ~145 ms，实测降到 ~122 ms、图标就绪提前约 40 ms）。
- 实测时间线（3 次冷启动）：`first frame 251/255/260 ms` → `worker first fetch 122–124 ms` → `全部可见图标 ~440–450 ms`。

**渲染后端 = glow(OpenGL)**，不是 eframe 默认。对比 wgpu：提交 464MB / 55 线程 / 881 句柄，画面逐像素一致。`MXRUN_RENDERER=wgpu` 是退路。

### 2.2 系统材质（E2）

- **Acrylic 可达**：`DwmSetWindowAttribute(hwnd, DWMWA_SYSTEMBACKDROP_TYPE, 3)` 在 egui/glow 的透明无边框置顶窗口上工作正常，能把背后内容（含其他窗口）糊成柔和色块。不需要换 WinUI。
- **Mica 不适合做启动器材质**：`DWMSBT_MAINWINDOW` 只采样壁纸、刻意不显示背后窗口，深色壁纸区域表现为死平暗色（实测像素恒定 `30,32,37`）。
- 开关（默认 off）：`MXRUN_BACKDROP=acrylic|mica|off|<n>`、`MXRUN_CARD_ALPHA=0-255`。
- **待处理**：材质会填满整个窗口矩形，现在"靠透明角做圆角"的做法会失效，圆角要改用 `DWMWA_WINDOW_CORNER_PREFERENCE`。

### 2.3 图标（E3）

- `IShellItemImageFactory` 取图，按 `24 * pixels_per_point` 请求像素、按 24pt 绘制。
- `cargo test` 实测覆盖：**exe(绝对路径) / exe(PATH 裸名) / 目录 / .bat / .lnk** 五类全部取到 48×48 真实像素；URL 与不存在的路径返回 None 走 emoji 回退。
- 索引构建时**一次性预热**，搜索热路径只查 HashMap。
- 遗留：URL 没有文件图标（要不要做 favicon 未定）。

### 2.4 启动期加固

- 单实例：`CreateMutexW("MxRun.SingleInstance.v1")`，重复启动弹提示后干净退出。
  **可升级**：AltRun 的做法是给已有窗口发自定义消息让它显示、自己退出（规格 §11），比弹框更顺。
- 启动失败（数据库/托盘/热键初始化）：弹 Win32 对话框说明原因 + 退出码 1，不再 `.expect()` 裸崩。
- 首帧句柄查找：**不要**用 `IsWindowVisible` 过滤——winit 首帧还没显示窗口，会导致启动不居中（已修）。

### 2.5 P0-1 命令模型落地（2026-09-13 完成并实测）

- **新模型**（定义在 `src/store.rs`，设计见 `命令模型设计.md` §4）：
  - 条目 = 标题 / 副标题 / **触发词（多值）** / **动作列表** / 参数规格 / 启动方式 / **来源** / 健康
  - 动作效果是**封闭集合**：打开 / 运行 / 内建 / 复制 / 定位（加能力就加动词，不加类型）
  - 参数规格 = **来源 + 编码 + 插入方式**三件独立的事（不再是一个枚举兼职四职）
  - 来源 = `provider + external_id`（导入幂等、识别"源里删了"、多来源互不干扰）
- **迁移安全**（三条一起做）：
  1. 所有结构 `#[serde(default)]` → 老记录仍能反序列化
  2. 迁移由 meta 的 **`schema_version`** 驱动（缺失 = v1）；迁移**只在版本落后时**跑（因为 v1 记录在加了默认值后会"成功解析成空条目"，这是个陷阱）
  3. **坏记录不再静默丢弃** → 写进 `Store::warnings`，再由 `main` 写 `mxrun.log`；**id 保持不变**（frecency 按 id 存，变了统计就脱钩）
- **实测验证**（用**真实库的副本** + 独立 `APPDATA` 跑，不动真库）：
  - 首次启动：`store: migrate: v1 -> v2, 6 条已转换`
  - 图标 `icons: 4/6 resolved` —— 4 条 exe 取到真图标、2 条 URL 走 emoji 回退，**这正好证明动作目标迁移正确**（图标是从动作里推导的）
  - 二次启动：**不再迁移**（幂等），图标仍 4/6（数据完好）
  - `backups/` 每次启动留一份，实测 2 份
- **搜索**：触发词进入搜索池并**加权**（精确 1000 / 前缀 400 / 包含 200）
  - 修掉了 v1 的老毛病：索引只拼 `name + desc`，关键字（`myip` 这种）**永远搜不到**
- **测试**：`cargo test` **12 项全过**（含"关键词命中压过模糊标题命中""只靠关键词也能搜到""三级权重顺序""旧库迁移保留 id""坏记录被上报""重复导入不产生重复"）
- **执行**：暂留**桥接**——只有「打开/运行」接到原来的 `open::that`，内建/复制/定位会提示"暂未实现"。**真执行器是 P0-2**（参数插入、启动方式、内建动词）。
- 顺带清掉的死代码：`kind_icon`/`kind_label`（9 分类没了）；`add_command`/`delete_command`/`export_json` 改名为 `upsert_item`/`delete_item`/`export_json` 并标注"给 CRUD/导入预留"。

### 2.6 P0-2 执行器（2026-09-13 完成并实测）

新增 `src/exec.rs`，`run(item, action)` 分派五种效果：

| 效果 | 调用 | 为什么是它 |
|---|---|---|
| `Open` | `ShellExecuteW` | 只有它能认文档/目录/网址/协议/CLSID/`.msc`/`.cpl`——这些都不是可执行文件 |
| `Run` | `CreateProcessW` | **带参数的命令行不是一个文件名**。AltRun 把整串交给 `ShellExecute`，只因后面那个 `WinExec` 兜底才没露馅（`untShortCutMan.pas:341-350`）；按效果拆开就没有这个陷阱 |
| `Builtin` | 进程内 Win32 | 显示桌面 = 给 `Shell_TrayWnd` 发 `MIN_ALL`(419)；隐藏/恢复 = `ShowWindow`；关机/重启 = `shutdown /s|/r /t 5`。**不引入外部 exe**。⚠️ **恢复窗口必须用"上一次被隐藏的那个句柄"**，不能用当前快照——等用户再次呼出时，前台窗口早已换成他刚点的那个了（AltRun 的 `WinCtl.exe UnHide` 不带参数也是这个原因） |
| `Reveal` | `explorer.exe /select,"…"` | |
| `Copy` | 剪贴板 | |

**参数机制落地**（`ArgSpec` 那三件事）：

- **编码**：原样 / URL / UTF-8。后两者在 Rust 里都是 UTF-8 百分号编码——AltRun 的差别只源于 Delphi 从 ANSI 字节编，现代化后两者等价（数据字段保留，行为统一）
- **插入**：`Replace` 会填 `{p}` / `%p` / `{%c}` 中出现的任何一种（AltRun 只替换**第一个**）；`Append` 追加到末尾——**搜索引擎就是靠它**
- **来源**：剪贴板、前台窗口（句柄/标题/类名）今天可用；**`Prompt` 没有界面 → 返回 `NeedsInput`**
- **前台窗口快照必须在呼出前取**（`show_window` 里调 `remember_foreground`）。否则"前台窗口"就是 MxRun 自己——AltRun 也是在热键按下瞬间取的值（规格 §4）

**`*` 标记（用户选的 C 方案）**：需要输入参数的条目，副标题显示「需要输入 *」；按回车不执行，而是提示"输入功能在下一步加入"。这样导入后不会让人以为程序坏了。

**顺带修掉两个图标缺口**（样本档案一跑就暴露，导入数据里全是这类）：

1. `%WINDIR%` / `%PROGRAMFILES%` 这类**环境变量目标**：图标解析前先展开
2. **裸名与带参数命令**：按 `PATHEXT` 在 PATH 里补扩展名解析——`nslookup`、`cmd /k %p`、`shutdown /s /t 5` 以前都取不到图标

实测：样本档案图标 **4/13 → 7/13**（剩下 3 条网址 + 2 条内建动作本来就没有文件图标）。

**测试**：`cargo test` **25 项**（新增 13 项）。其中两项是**真的动了系统**的端到端测试：

- **真实窗口的隐藏/恢复**：真起 notepad → 按应用的方式快照前台窗口 → 用执行器自己的动词隐藏 → 用 Win32 `IsWindowVisible` 校验 → 恢复 → 杀掉。**而且它是安全的**：如果前台窗口不是 notepad（比如是你的终端），它会**跳过而不是失败**——绝不会去隐藏别的窗口
- **剪贴板往返**：写进去再读回来，读之前先保存原内容、测完还原；**剪贴板里没有文本时直接跳过**（避免把复制的图片毁掉）

仍未自动化的只有**界面交互**本身（键盘输入进不了 egui，见 CLAUDE.md 踩坑 3）。

### 2.7 P0-3 导入器（2026-09-13 完成并实测）

新增 `src/import.rs` + `--import` 开关（GUI 程序没有控制台，所以结果既写 `mxrun.log`，也弹一个汇总框）。

**用真实文件实测**（2026-09-14 已代为导入到真实数据目录 `%APPDATA%\MxRun`）：

```
import: lines=76 commands=72 imported=59 needs_input=4 builtin=4 removed_seed=6 skipped(sep=4 unwanted=13 unsupported=0)
icons: 47/59 resolved
```

**导入会自动清掉演示数据**（`removed_seed=6`）：新库的种子条目 provider 是 `seed`，而 v1 老库迁移出来的是 `legacy`——两种都要删，否则列表里会出现"计算器"和导入的 `Calc` 并存这类重复。判断依据写在 `DEMO_PROVIDERS` 常量里，注释说明了为什么 `legacy` 也一定是演示数据（v1 的 `add_command` 从未被调用过，用户不可能加过自己的命令）。

**踩到的坑（值得记）**：第一版只按 `provider == "seed"` 删，结果真实库 `removed_seed=0`——因为用户那 6 条是老格式迁移来的（`legacy`）。单元测试当时用的是新库（`seed`），没能覆盖这条路径；现在测试会先把 provider 改成 `legacy` 再验。

**两条不照抄的规则**（都在代码里，`--import-all` 可关掉）：

1. **不灌 `F<n>` 权重** —— 那是作者模板里的预置值（§6.1.1），灌进来等于把一个十几年前、不衰减的排序冻进 frecency
2. **`@.\WinCtl.exe …` 映射成内建动词**（显示桌面 / 只显示当前窗口 / 隐藏 / 恢复），并**丢掉那个 `@` 前缀**（它原本只是"别让助手 exe 闪窗口"）

**跳过 13 条**：12 条无用条目（IE、Internet 控制、添加删除程序、系统属性、`%WINDIR%`/System32/ProgramFiles 三个目录、`.\ALTRun.ini`、升级死链、搜狗MP3、VeryCD、Yahoo）+ **1 条用户明确不要的**：`cmd`（Dos窗口，`cmd /k %p` —— 一个先弹框问你"要运行什么"的条目，用户 2026-09-13 确认不会用到）。

**关键实现细节**：

- **编码**：文件是 GBK（Delphi 写的是 ANSI 代码页）。用 Win32 `MultiByteToWideChar(CP_ACP)` 解码，**不引入新依赖**（已在用 `windows` crate）；UTF-8 文件也照样读
- **命令行里含 `|`**：只 `splitn(5, '|')`，第五列保留原样（URL 里可能有 `|`）
- **打开还是运行**：URL/`::`/`shell:`/`ms-settings:` → 打开；**目标后面带参数 → 运行**（`cmd /k %p`、`shutdown /s /t 5`）；只有一个目标 → 打开
- **参数规格从数据推导**：`{%c}`→剪贴板、`{%wd}`→前台窗口、其余非空编码列→需要输入；有占位符→替换，没有→追加（搜索引擎的机制）

**实测查询**（用导入后的档案，自检开关）：

| 查询 | 结果 | 说明 |
|---|---|---|
| `stea` | **1 条**（目标应用） | 关键字前缀命中 |
| `cb` | **1 条**：百度 搜索剪贴板 | ⚠️ `needs_input=false` —— 见下面的 bug |
| `hide` | 2 条：隐藏本窗口 / 恢复窗口 | 两条都是内建动作，都合理 |
| `dos` | 8 条（Dos窗口 排第 1） | 关键字是 `cmd` 不是 `dos`，只能靠标题模糊匹配 → 噪音仍在 |

**顺带修掉的一个真 bug**：`wants_input()` 原本写成"输入来源 ≠ 无"，于是**剪贴板搜索（`cb`/`cg`）也会被标成"需要输入"**——但它们根本不用打字。改成只认 `Prompt`。单元测试当场抓住了它（`search_engines_append_and_clipboard_ones_replace`）。

**同批做的小改进：搜索分数闸门**（`SCORE_GATE = 0.15`）
低于最高分 15% 的结果不再显示。实测效果：`stea` 从一堆噪音变成 1 条、`cb` 1 条、`hide` 2 条。

### 2.9 启动次数统计 + 行内容补全（2026-09-14）

用户提出："每个项目的启动次数要统计，并显示在列表项里（现在列表项很空）"。

### 2.10 P1-1 输入机制（2026-09-15 完成，端到端实测）

用户拍板：**形态 = 顶框切换式**（不新开窗口），**参数历史 = 做**（存进 redb，不新增文件）。

**交互**（对齐 `AltRun交互规格.md` §3 的两段式，只是把 `frmParam` 从独立窗口搬进主窗口）：

| 步骤 | 行为 |
|---|---|
| 选中带参数的条目 → Enter/空格 | 顶框变成参数框：左边一个琥珀色小标签（`⌘ 百度搜索`），右边是输入框；列表换成该条目的参数历史 |
| 输入 | 每敲一字重算建议（子串匹配、忽略大小写）；**空格照常输入**（主框里空格是"执行"，这里不是） |
| ↑ / ↓ | 高亮历史项（高亮 ≠ 改写输入框内容）；回车执行**高亮项**，没高亮就执行**手输内容**，两者在底部提示行里写明 |
| 单击建议 | 填进输入框（不直接执行）——历史参数常常要改一下才用，原版下拉框也是这个行为 |
| 回车（空输入） | 不执行，留在输入态并提示（原版对话框同样拒绝） |
| Esc | 两级：先清空输入 → 空后再退回搜索（与主框、与原版 `frmParam` 都是同一套语义） |
| 窗口隐藏 | 提示一并丢弃（下次呼出是干净的搜索态） |

**落地的三件事**：

1. `exec::run_with_arg(item, action, Some(text))` 是新的执行入口；`run()` 退化成 `run_with_arg(…, None)`。`ArgSource::Prompt` 拿不到文本时仍然返回 `NeedsInput`——**而 `NeedsInput` 正是 UI 打开提示的信号**（执行器不认识 UI，UI 只认这一个返回值）
2. **参数历史存 meta 表**（键 `param:<条目 id>:<参数>`，值是使用次数）：按条目分开记（"我常开的那个 wiki 页"和"我常搜的词"不再抢同一个名额），上限 50（对齐原版 `ParamHistoryLimit`），超限丢使用次数最少的。**不新增文件**——原版是 exe 旁边的 `ParamHistory.txt`
3. `BuiltinVerb::RunInput`（原版「运行」）接上了：输入当命令行执行，`LaunchMode` 强制 Normal（条目自己的 Hidden 会让"运行我输的东西"看不见窗口，那不是本意）。⚠️ 目前**没有条目产生这个动词**，属预留能力（§3 P1-4 的"运行/兜底"还没做）

**实测证据（无键盘跑通全链路）**——用样本档案里新加的 `p11` 条目（`cmd /c echo {p} > "%TEMP%\mxrun-p11-param.txt"`，Hidden 启动，无窗口闪现）：

```
MXRUN_SELFTEST=p11 MXRUN_SELFTEST_EXEC=1 MXRUN_SELFTEST_PARAM=hello-param-11
→ selftest: query="p11" rows=1 · row0 needs_input=true
→ prompt: open for "参数写入文件" (history=0)
→ execute: 参数写入文件 (+parameter, 14 chars)
→ %TEMP%\mxrun-p11-param.txt 内容 = "hello-param-11"      ← 参数真的进了真实进程
第二次：history=1 suggestions=1（用过的参数被记住并出现在建议里）
第三次：history=1 suggestions=0（输入无关文字时建议被过滤掉）
```

**测试**：`cargo test` **51 项**（新增 11 项）。其中 `typed_parameter_reaches_a_real_process` 是**真起进程**的端到端测试：条目 `cmd /c echo {p} > <临时文件>`，先用 `run()` 断言必须 `NeedsInput`，再用 `run_with_arg(…, "hello-param")` 断言**文件里真有这串字**——这是我们自己的字符串处理之外、唯一能证明"参数没被吞掉"的证据。

**仍未验证的部分（诚实记一笔）**：跑在本机自动化环境里时窗口拿不到前台，`hide: lost focus` 会在 ~300ms 后把窗口收掉，而 GDI 截图**看不见这个窗口**（§7 踩坑 12）——所以**参数输入界面的实际画面与键盘手感（空格、↑↓、Esc 两级）没有机器证据**，需要人眼过一遍（三分钟，见 §9 第 6 条）。逻辑层面（状态机 / 过滤 / 编码 / 落库）都有单元测试与上面的真进程证据。

### 2.11 加项闭环：右键进得来、F2 改得动（2026-09-15 完成，双进程实测）

**背景**：在此之前 MxRun **一条加项入口都没有**——库里 59 条只能靠改 AltRun 的清单再 `--import`，
而"右键 → 发送到 → ALTRun"是用户用了十几年的习惯（`AltRun交互规格.md` §11 实测：本机 `SendTo\ALTRun.lnk` 存在、
`AddToSendTo=1`；原版的 shell 右键菜单是死代码、零调用点）。

**五个入口，一张卡片**（都落到同一个"小确认框"）：

| 入口 | 怎么触发 | 预填 |
|---|---|---|
| 发送到 | 右键文件 → 发送到 → MxRun | 由路径推导（见下） |
| 右键菜单 | 文件 / 目录 / 目录空白处 → "用 MxRun 添加(&M)" | 同上 |
| 命令行 | `MxRun.exe "<路径>"`（也支持拖一堆文件到 exe 上） | 同上，多选排成队列 |
| 托盘"新建条目…" | 托盘右键菜单 | 三个框全空 |
| 无匹配回车 | 输入一个搜不到的词直接回车（原版"无此项，添加它?"） | 关键字/名称 = 输入的词，命令行留空 |

**预填规则照原版 `frmShortCut`**（`untShortCutMan.pas:799-882`）：`.lnk` 先解析到真实目标
（两种例外保留 lnk 本身：解析不出来、目标落在 `%windir%\Installer\` 的 MSI 图标 exe）；
**关键字 = 文件名去扩展名，目录不切**（`node.js` 不能变成 `node`）；URL 取主机名；
名称 = 关键字；命令行 = 完整路径。

**"不打扰"是这套交互的灵魂**（原版两种情况下都**不显示主窗口**，只弹一个小框）：

- 第二个实例**只写一个请求文件就静默退出**——不弹"已经在运行"，也不显示主窗口
- 运行中的实例由**后台线程**每 100ms 收一次（它本来就在为热键/托盘轮询），然后把窗口**按卡片尺寸**显示出来
- 也就是说：请求到达时窗口还没出现，出现时就已经是小卡片了，**不会先闪一下主列表**
- 卡片里改完 → 回车 → 落库 → 窗口直接收起，回到 Explorer

**为什么用文件而不是窗口消息**：AltRun 给已有窗口发 `WM_SETTEXT`，而 eframe/winit 不给我们接收任意窗口消息的入口
（事件循环在 winit 手里）。通道是 `%APPDATA%\MxRun\inbox\` 目录：写临时名再 `rename`（读者永远看不到半截文件）、
读完即删、空文件 = "只是唤醒"（等于用户又双击了一次 exe，原版这里是弹"已经在运行"）。
副作用是**顺手修掉了原版的一个缺陷**：原版加项路径绕过单实例检查，两个实例可能同时写列表文件；MxRun 走交接，只有一个写者。

**落库**：`provider = "manual"`，`external_id` = 小写化的原路径 → **同一个文件再加一次是"更新"而不是"新增"**，
启动次数跟着走。F2 编辑则保持原 id 与来源（不碰 `arg` 规格、启动方式、多触发词里的第 2 个以后）。
关键字撞车时：**第一次回车只警告**（"已被「记事本」使用 —— 再按一次回车将覆盖它"），**第二次才覆盖**——
原版是弹模态问一句，这里把同一个问题变成一次按键，符合它"确认框必需但别啰嗦"的意图。

**F2 的归属**：原版 F2 = 编辑当前项，MxRun 之前拿 F2 当设置页 → **按原版对齐**：F2 = 编辑，
设置移到托盘菜单（原版也把"配置"放在托盘菜单里，还带 `Alt+C`）。托盘菜单同时新增"新建条目…"。

**入口注册是显式按钮**（设置页两行 + `--install-integration` / `--uninstall-integration` 开关），
**不在启动时偷偷写**：写 `SendTo` 与注册表是对用户系统的可见改动，该由他点一下。
右键菜单写在 `HKCU\Software\Classes\{*|Directory|Directory\Background}\shell\MxRun`（**免管理员**；
原版写的 `HKCR` 且从未被调用）。

**实测证据**（全部无键盘，用临时档案跑，真实数据没动）：

```

   B: handoff: sent 1 path(s) to the running instance (…inbox\req-…txt)   ← B 退出码 0、没窗口
   A: handoff: received 1 path(s) → add: open for "…\My Test Tool.exe"
   A: add: created "My Test Tool" -> …\My Test Tool.exe      status="已添加：My Test Tool"

   selftest: editing "记事本" (id=seed-1, launches=1)

   after edit: id=seed-1 title="记事本" command=Some("notepad.exe --mxrun-selftest")   ← id 没变 = 启动次数没丢
```

**三种"当时它在不在跑"的情况都实测过**：

| 情况 | 行为 | 实测 |

| **MxRun 正在跑（显示或隐藏都算）** | 第二个实例把路径写进 inbox 后静默退出；主实例把窗口**按卡片尺寸**显示出来 | 隐藏状态下的验证：日志先 `hide: lost focus`（被 notepad 抢走前台），3 秒后 `handoff: received` → `add: open` → `add: created` → `add: done, hiding`。**卡片能被收下就说明窗口确实被重新显示并出帧了**（收件逻辑跑在 `ui()` 里，隐藏的窗口不出帧） |

### 2.12 便携化与自愈（2026-09-16 完成，实测）

**起因（用户提问）**："这个项目最终是做成便携版的话，这个加项的功能要怎么添加到一台没有下载安装过 mxrun 的电脑？"
——当时那套集成有两个漏洞：路径写死成**绝对路径**（换机器/换盘/改目录名就断），"要不要集成"这个意图又只存在 `%APPDATA%`（每台机器一份，不跟着便携文件夹走）。

**三件事一起做**：

| # | 做什么 | 怎么做的 |
|---|---|---|
| 1 | **便携数据模式** | exe 旁边放一个空的 `portable.txt` → 数据库、备份、日志、交接收件箱全在 `data\` 里（`store::default_data_dir` 一处判定，`log_line` 也跟着走）。整个文件夹随便拷，配置与"右键集成是我的"这个事实一起跟着走 |
| 2 | **启动自愈** | **注册本身就是意图记录**，不另存开关：启动时如果"注册存在，但不是指向我" → 静默重写（`repair_if_registered`）。所以文件夹改名/换盘符后**跑一次就自动修好**；而"什么都没注册"不会被当成疏漏（那是用户的选择），绝不擅自添加 |
| 3 | **首次运行问一次** | 只有当"这台机器上什么都没注册"且"没问过"时才弹一张卡片问要不要加入右键。标记写在 `%LOCALAPPDATA%\MxRun\integration-asked`——**故意不放在数据目录**：便携目录会跟着走，而"这台机器的资源管理器认不认识 MxRun"是**机器本地事实**。答"加入"或"不用了"都算答过，不再追问；窗口被隐藏则算"以后再说"（不写标记，下次再问） |

**新机器上的完整体验**：把文件夹拷过去 → 双击 `mxrun.exe` → 问一次"要不要加进右键菜单" → 选"加入" → 以后每次启动自动把路径校准到当前副本。

**实测（全部临时目录，跑完已清理；你机器上的注册已还原成指向 `target\release\mxrun.exe`）**：

```
① 便携模式：<portable>\mxrun.exe + portable.txt →
   日志 startup: data_dir=…\mxrun-portable-A\data portable=true
   目录内容：data\mxrun.log、data\mxrun.redb；而伪造的 %APPDATA% 里"什么都没有"
② 自愈：把 mxrun-portable-A 整个改名成 -B →
   移动后注册表仍指向 A（这就是原来会断的样子）
   跑一次 B\mxrun.exe → self-heal: 发送到 已重新指向 …\mxrun-portable-B\mxrun.exe
                        self-heal: 右键菜单 3 处已重新指向 …\mxrun-portable-B\mxrun.exe
③ 首次询问：先卸干净（模拟新机器）→ 启动 → integration: nothing registered on this machine, asking
   →（脚本代答 yes）→ 已加入右键菜单（3 处）和「发送到」→ 注册表与 SendTo 都指向 B
   → 机器本地标记落在 %LOCALAPPDATA%\MxRun\integration-asked
```

**顺带说明（也是坑）**：便携副本与 `%APPDATA%` 正式版各自一个数据库（启动次数、参数历史分开算），
而**单实例互斥体是全局的**——两个一起跑会互相顶掉。同一台机器上建议只留一个。

**给用户的加项通道优先级**（便携场景下不进系统也能用）：
拖文件到 `mxrun.exe` 上（支持多选排队）→ `MxRun.exe "<路径>"` → 搜索无匹配回车添加。
**系统集成是"可选加强"，不是加项的前提。**

**调试开关**：`MXRUN_SELFTEST_INTEGRATION=yes|no` 无键盘回答首次询问（只用于脚本验收）。

### 2.13 删除 + 快捷项管理（2026-09-17 完成，实测）

**背景**：在这之前能加、能改，**但删不掉**，也没有一个"把条目都列出来看看"的地方（列表只在搜索时出现）。
原版对应的是 `Delete` 键 + 托盘"快捷项管理"（`frmShortCutMan`，四列：ShortCut / Name / Param Type / Command Line）。

**三个入口**：

| 入口 | 行为 |
|---|---|
| 列表/管理器里按 `Delete` | 第一次按**只问**（状态行："再按一次 Delete 删除「X」（其它按键取消）"，行变红），第二次才删。原版是弹模态确认框（`frmALTRun.pas:2233-2241`）——**问题一样，只是不要那个框**，比照加项卡片"关键字撞车"的处理 |
| 行右键菜单 | 编辑 / 删除 / 打开所在目录（原版列表右键是"添加/编辑/删除/-/打开所在目录"，"添加"仍在 Insert 与托盘上） |
| 托盘 → **快捷项管理…** | 打开管理视图（原版托盘菜单第二项就是它，还带 `Alt+S`） |

**管理视图**（同一个窗口、换一种列表，尺寸放宽到 880×560——原版给命令列留了 400px，同样的理由）：

- **显示全部条目**（不走分数闸门、不受 8 行上限约束，改用滚动条），默认**按启动次数排序**、次数相同的按标题——"没启动过的一堆"自然沉在底部，正是收拾东西时要找的
- 顶部筛选框就是熟悉的搜索框（同一套匹配），筛 59 条和平时搜索手感一致
- 键位照原版：`F2` 编辑、`Insert` 新建、`Delete` 删除、**双击编辑**（管理器里没有"执行"这回事，所以回车也做成编辑）
- 额外：`Ctrl+D` 定位到文件（原版也有）、`Esc` 返回启动器
- **故意不照搬原版管理器的三个缺陷**：拖拽重排（会丢 Freq）、内联改名（绕过重名检测）、"编辑不动内容直接确定"被自己判重而静默丢弃

**存储层的两件事**（这是"删除"能站得住脚的关键）：

1. **删除会连带清掉统计**：`frec:<id>` 与 `param:<id>:*` 一起删。它们按 id 存，留着会让后来恰好复用同一 id 的条目"继承"被删条目的次数
2. **墓碑（tombstone）**：给 `(provider, external_id)` 记一条 `gone:` 键。没有它，"删除"对导入条目就是**谎话**——下次 `--import` 会原样搬回来。导入器现在跳过并计入 `skipped_deleted`，汇总框会写"你在 MxRun 里删过的 N 条没有再加回来"。
   **但"手动再加一次"会清掉墓碑**：导入不该复活被删的东西，而用户主动添加是改变主意，不是复活（`clear_deleted`）。
   顺带留了 `deleted_sources()`，"已删除 / 撤销"列表以后可以直接用它。

**实测（临时档案；导入 → 删除 → 再导入，全程无键盘）**：

```
① 管理器与两步删除
   manage: open (6 items) → selftest: manage rows=6 items=6
   delete: confirm? "Bing"            → 状态="再按一次 Delete 删除「Bing」（其它按键取消）"
   delete: removed "Bing" (id=seed-4, provider=seed) → index: 5 items → 状态="已删除：Bing"
② 墓碑真的挡住重新导入
   第一次 --import：lines=2 imported=2 removed_seed=6
   管理器里删掉 BBB Tool（id=shortcutlist:line:2）
   第二次 --import：import: 跳过你删过的条目：BBB Tool
                    lines=2 imported=1 … deleted=1        ← 没回来
```

**测试**：`cargo test` **71 项**（新增 3 项：删除连带清统计 + 墓碑 + 主动添加清墓碑；删演示条目不留墓碑；导入跳过被删条目）。

**调试开关**：`MXRUN_SELFTEST_MANAGE=1` 打开管理器、`MXRUN_SELFTEST_DELETE=1` 顺手把选中项删掉（**真删**，只对临时档案用）。

**仍要人眼确认**：管理器那一屏的排版（四列挤不挤）、`Delete` 两步的手感、右键菜单里的三项。

### 3.1 右键集成的三条设计约束（**已实现，留档**）

从 §2.8 的 AltRun 实测行为反推——实现时别丢：

1. **"不打扰"是这个交互的灵魂**：只弹一个加项小确认框，**主窗口全程不显示**（原版"已运行"和"未运行"两种情况都不显示）。顺手把主窗口拉出来，手感就变了。

## 7. 踩坑记录（本次新增，避免重复踩）

1. **egui 空闲时不调用 `ui()`** —— 任何轮询式检查（如失焦检测）都必须配 `ctx.request_repaint_after(...)`，否则是死代码。
2. **`MainWindowHandle` 不是可见性探针** —— 它是句柄。判断窗口是否可见要用 Win32 `IsWindowVisible`。
3. **`SendKeys` 只送到前台窗口** —— 从自动化环境启动的 MxRun 拿不到键盘焦点，按键会落到别的窗口（有误伤风险）；`WM_CHAR` 投递也进不了 egui。**自动化测试不能验证键盘交互，必须人工确认**。
4. **运行中的实例会锁住 `target/release/mxrun.exe`** —— 重新构建前先关掉实例，否则 cargo 报 `拒绝访问 (os error 5)`。**构建后务必看一眼 exe 时间戳**。
   **而且它还会干扰测试**：残留实例会抢前台窗口，让"真实窗口隐藏/恢复"那条端到端测试失败。跑测试前先 `Get-Process *mxrun* | Stop-Process -Force`。
5. **控制台编码 / 读日志**：PowerShell 输出中文会乱码；读 UTF-8 日志必须用 `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)`，否则满屏乱码（**文件本身没坏**）。
6. **不要用 `Add-Type -MemberDefinition` + `\"` 转义** —— PowerShell 的转义符是反引号，用 here-string `@"..."@` 更稳。
7. **COM 是按线程的** —— 图标 worker 线程必须自己 `CoInitializeEx`，不能复用主线程的进程级 `Once`。
8. **`OnceLock` 懒初始化会骗人** —— `us_since_start()` 原来在第一次调用时才锚定起点，于是第一个调用者永远读到 0（我据此误判过"图标瞬间就绪"）。时钟要在 `main` 里锚定。
9. **PowerShell 里 `$env:VAR = ""` 等于删除变量** —— 想给程序传"空字符串"（自检开关的空查询）做不到，得换哨兵值或干脆不设。
10. **视觉工具会限流** —— `vision_describe` 返回 `VISION_RATE_LIMITED` 时改问法重试**没用**；本机也没装 tesseract（`spawn tesseract ENOENT`）。UI 截图验证要靠人工看一眼，或等下一轮再读。
11. **"看起来像遥测数据"的字段先查来源再信** —— AltRun 的 `F<n>` 我当成"使用次数"分析了一整轮，其实是作者模板里的预置权重（§2.7 与 `命令模型设计.md` §6.1.1）。**数据的出处比数据本身更重要。**
12. **GDI 截图拍不到这个窗口（2026-09-15，新踩）** —— 窗口 `IsWindowVisible=True`、位置尺寸都对，但 `CopyFromScreen` / `PrintWindow` / 带 `CAPTUREBLT` 的 `BitBlt` 三路都只能拿到**窗口背后的壁纸**（三路都用像素统计验证过：卡片色占比 0%、无亮字像素）。原因是 DWM 把 GPU 合成的窗口提到了**硬件叠加平面（MPO）**上，GDI 抓的是它下面的桌面。换 `MXRUN_RENDERER=wgpu` 一样。**结论：本机自动化截屏这条路不可用**，UI 视觉只能人工看；要用机器证据就得走 WinRT `Windows.Graphics.Capture`（成本高，暂不做）。
    顺带：自动化启动的进程**拿不到前台**，窗口会在 ~300ms 后 `hide: lost focus` 自己收起来，所以截图窗口期本来也不存在——为人工/后续排查加了个开关 `MXRUN_KEEP_OPEN=1`（关掉失焦隐藏）。
13. **harness 的 shell 是 Windows PowerShell 5.1，`Set-Content`/`Get-Content` 默认按 ANSI 处理** —— 2026-09-15 用 `(Get-Content -Raw) -replace … | Set-Content` 批量改 `main.rs`，把文件里的 UTF-8 中文与破折号**整片改成 `?`**（文件当场不是合法 UTF-8，cargo 报 "stream did not contain valid UTF-8"）。**改源码只用编辑器/`edit` 工具，永远不要用 PowerShell 文本管道重写带中文的文件**；读日志要显式 `[Text.Encoding]::UTF8`（见踩坑 5）。恢复办法：`git checkout -- <文件>` 后重做改动（当时改的都是本回合的编辑，代价可控）。
14. **PowerShell 里注册表路径含 `*` 会被当通配符炸开（2026-09-15，新踩）** —— `Test-Path "HKCU:\Software\Classes\*\shell\MxRun"` / `Get-ItemProperty` 同类写法会把 `*` 展开成 `HKCU\Software\Classes` 下的**所有类**，命令直接卡死（实测 120s 超时）。查这种路径要么 `-LiteralPath`，要么用 `reg query "HKCU\Software\Classes\*\shell\MxRun" /s`（`reg.exe` 不做通配）。
15. **`message_box` 会挡住脚本** —— `--import` / `--install-integration` 这类无窗口模式最后都会弹一个 Win32 汇总框，从脚本里 `Start-Process … -Wait` 会一直等下去。检查产物要在弹框**之后**、杀进程之前（`Get-Process *mxrun* | Stop-Process -Force` 会顺带关掉框）。
16. **剪贴板测试会被桌面上别的东西抢**（2026-09-16，新踩）—— `clipboard_round_trip` 写过探针后立刻读回，在有剪贴板管理器/输入法助手（用户正坐在电脑前用着）时会读到 `None` 而**失败**。修法：**先把用户的剪贴板还原，再断言**（失败绝不能把探针留在人家剪贴板里），探针读不回来时**跳过而不是失败**——那是环境在说话。同一类问题：任何"独占全局资源"的测试都要这样写。
17. **提交前钩子真的会拦自己人** —— 我在测试里写了个假用户目录路径（就是"`C:` + `\Users\` + 一个字母"那种形状），被 `pre-commit` 当成真实路径拒了两次（第二次是**文档里引用它**）。**这是钩子在正常工作**：假路径也别用那个形状，改用别的盘符 + 中性目录名（如 `R:\roaming`）；连"引用一下"都不行，写坑记录时用文字描述形状。

## 8. 环境与操作要点

```bash
export PATH="<MinGW-w64>/bin:$HOME/.cargo/bin:$PATH"   # 真实路径见 local/机器环境.md
cd <项目目录>
cargo build --release     # → target/release/mxrun.exe（构建前先关掉运行中的实例）
cargo test                # 51 项单元测试（模型/迁移/搜索/执行器/导入器/参数提示）
```

- 数据目录 `%APPDATA%\MxRun\`（`mxrun.redb` + `backups/` + `mxrun.log` + `inbox/`）
  - **便携模式**：exe 旁边放一个空的 `portable.txt` → 数据全部改到 exe 旁的 `data\`（数据库/备份/日志/收件箱），整个文件夹可以随便拷（§2.12）
  - 同一台机器上便携副本与 `%APPDATA%` 正式版是**两个独立数据库**，且单实例互斥体是全局的——别同时跑
- **`mxrun.log` 是排查主力**：记录 renderer / `index:` 索引构建 / `frame: first` 冷启动首帧 / `icons:` 图标（首帧就绪、worker 空闲）/ `wake:` 呼出延迟 / `hide:` / `execute:` / `import:`。写代码时值得继续往里加事件
- 用独立数据目录做实验：`APPDATA="$TEMP/mxrun-test" ./target/release/mxrun.exe`
  （注意：单实例互斥体是**全局**的，不随 APPDATA 变化）
- 温度开关：`MXRUN_RENDERER=wgpu`、`MXRUN_BACKDROP=acrylic`、`MXRUN_CARD_ALPHA=n`、`MXRUN_KEEP_OPEN=1`（关掉"失焦即隐藏"，方便盯着窗口看/排查）
- **导入开关**：`mxrun.exe --import`（精选）/ `--import-all`（全量）；源文件默认取 `$MXRUN_ALTRUN_LIST`，也可在开关后面直接给路径
- **右键集成开关**：`mxrun.exe --install-integration` / `--uninstall-integration`（等于设置页那两个按钮：写 `SendTo\MxRun.lnk` + `HKCU\Software\Classes\{*|Directory|Directory\Background}\shell\MxRun`）。两者都会弹一个 Win32 汇总框（见踩坑 15）
- **便携**：exe 旁边建一个空的 `portable.txt` 即可（数据进 `data\`）；移动/改名文件夹后**跑一次就自动修正**注册路径
- **机器本地状态**：`%LOCALAPPDATA%\MxRun\integration-asked` = "这台机器已经问过要不要集成"（故意与数据目录分开，见 §2.12）
- **加项命令行**：`mxrun.exe "<路径>"`（可多个）——已有实例在跑就交接给它并静默退出；没有实例则以卡片尺寸启动并直接打开确认框
- **隐私（2026-09-14 起，仓库是公开的）**：个人路径/用户名/软件清单一律不进被跟踪的文件——放 `local/`（已忽略），文档用 `<占位符>`。
  `.githooks/pre-commit` 会在提交前扫描并拦截（拦截词在 `local/personal-patterns.txt`）。**换机器 clone 后要执行一次 `git config core.hooksPath .githooks`**，否则钩子不生效。
  提交前自查：`git grep -n -E "<你的私有关键词>"`（钩子偶尔会被 `--no-verify` 绕过）。
  ⚠️ 参数历史存在库里（`param:` 键），跟原版的 `ParamHistory.txt` 一样是**明文**——搜过的词、路径都在里面，这是功能本身要的；但**不要把它打进日志或导出到仓库**（`export_json` 不含它）。
- **自检开关（无键盘验收用）**：`MXRUN_SELFTEST=<查询>` 启动时自动填入关键字、跑**真实**搜索，把每行结果（标题/类别/是否需要输入/得分）写进 `mxrun.log`；再加 `MXRUN_SELFTEST_EXEC=1` 会执行第一行（只对"拒绝执行"的条目安全，比如需要输入的）。
  需要参数的条目：`MXRUN_SELFTEST_EXEC=1` 会**打开参数提示**（不执行），再加 `MXRUN_SELFTEST_PARAM=<文本>` 才会真的把参数交给命令行执行——**它会真执行**，务必配一个无副作用的样本条目（样本档案里的 `p11` 就是：写一个临时文件，见 §2.10）。
  **`MXRUN_SELFTEST_ADD=1`**：收到交接进来的路径后自动把确认卡"按两次回车"走完（第一次警告关键字撞车、第二次覆盖），用于验证右键链路；**它会真的写库**。**`MXRUN_SELFTEST_EDIT=1`**：对第一行执行 F2 编辑 → 改命令行 → 保存，验证 id/启动次数不丢；**同样会真的改库**。这两个只对**临时档案**用（`$env:APPDATA=$env:TEMP\...`）。
  **这是唯一能在没人按键的情况下验证"搜索 → 列表 → 参数 → 执行"链路的办法**——`SendKeys` 只会送进当前前台窗口（踩坑 3），自动化环境里会误伤别的窗口。
  实测输出示例（查询 `dos`）：`row0 title="Dos窗口" category=命令 needs_input=true score=1088.0`；`p11` 与加项链路见 §2.10 / §2.11。
